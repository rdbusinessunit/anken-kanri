# 通知メールの設定手順

毎朝、担当者ごとに「対応が必要な案件」をメールで送る仕組みです。
誰も画面を開いていなくても届きます。サーバーを新しく立てる必要はありません。

判定の中身は画面の「対応が必要」とまったく同じです。新しい条件は作っていません。

**作業は30分ほどです。** 1〜4はSupabaseとResendの画面での操作なので、ご本人にお願いします。
パスワードやAPIキーは誰にも渡さず、直接それぞれの画面に入力してください。

---

## 1. メール送信サービスに登録する

[resend.com](https://resend.com) に登録します。**無料で月3,000通・1日100通**まで送れます。
担当者10人に毎日1通でも、月300通ほどなので余裕があります。

1. 登録したら **API Keys** から鍵を1つ作り、控えておく（この画面を離れると二度と見られません）
2. 差出人アドレスを決める
   - **すぐ試すなら** `onboarding@resend.dev` をそのまま使えます。届きますが、差出人が
     Resendのドメインになるため迷惑メールに入ることがあります
   - **本運用では** Domains から自社ドメインを登録してください。差出人が自社アドレスになり、
     迷惑メール扱いされにくくなります。DNSへの登録が必要なので情報システム部門に依頼します

## 2. 関数をSupabaseに登録する

Supabaseのダッシュボード → **Edge Functions** → **Deploy a new function**。

- 名前：`daily-alert`
- 中身：このフォルダの `functions/daily-alert/index.ts` を全部貼り付け

## 3. 鍵を登録する

Edge Functions → **Secrets** に、次の3つを追加します。

| 名前 | 値 |
| --- | --- |
| `RESEND_API_KEY` | 手順1で控えたAPIキー |
| `MAIL_FROM` | `案件管理システム <onboarding@resend.dev>`（自社ドメイン登録後はそのアドレス） |
| `APP_URL` | `https://rdbusinessunit.github.io/anken-kanri/` |

`SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` は最初から入っているので触りません。

## 4. 毎朝動かす

SQL Editor で次を実行します。`<プロジェクトURL>` と `<service_role キー>` は
Settings → API の値に置き換えてください。**毎朝8時（日本時間）**に動きます。

```sql
select cron.schedule(
  'anken-daily-alert',
  '0 23 * * *',  -- UTC 23:00 = 日本時間 翌朝8:00
  $$
  select net.http_post(
    url     := '<プロジェクトURL>/functions/v1/daily-alert',
    headers := '{"Content-Type":"application/json","Authorization":"Bearer <service_role キー>"}'::jsonb
  );
  $$
);
```

時刻を変えるときは `'0 23 * * *'` の部分を直します（UTCなので日本時間マイナス9時間）。
止めるときは `select cron.unschedule('anken-daily-alert');` です。

動いたかどうかは `select * from cron.job_run_details order by start_time desc limit 10;` で見られます。

## 5. 宛先を入れる

ここからはシステムの画面です。**設定 → 通知メール** に、
担当者ごとのメールアドレスを `担当者名｜メールアドレス` の形で1行ずつ入れます。
担当者名は案件の「営業担当」と同じ表記にしてください。一致した人にだけ届きます。

全担当分をまとめて受け取りたい人（所長・RDなど）は、下の欄にアドレスだけ入れます。

最後に「送信」を **送る** にして保存します。止めたいときは **送らない** に戻せば、
アドレスを消さずに停止できます。


## 何を・誰に・いつ送るか（決定済み）

**送る条件（4つ）**

- 稟議が止まっている（簡易求人を発注したのに未上申／差戻しのまま／決裁が止まっている）
- 承認済みなのに③詳細が未入力で、面接・進捗報告ができない
- 求人の修正日を過ぎた
- 未着手の課題がある

承認後の条件変更とRD未確認は、画面には出しますがメールでは送りません。

**宛先**

- 営業担当本人 … 自分が担当する案件だけ
- 所長・RD … 全担当分をまとめた一覧

設定画面の「通知メール」で登録します。

**頻度**

毎朝8時（日本時間）。該当する案件が1件もない日は送りません。

---

## 先に1通だけ試す

手順4の前に、Edge Functions の画面から `daily-alert` を手動で実行できます。
`{"ok":true,"sent":2,"cases":5}` のように返れば成功です。
`sent:0` のときは、設定が「送らない」になっているか、担当者名が一致していません。

## 注意

- 判定は `core.js` の `alertsFor()` と同じ内容を写したものです。**条件を変えるときは両方直してください。**
  片方だけ直すと、画面とメールで言うことが変わります
- 対応が必要な案件が1件もない日は、メールを送りません
- この仕組みが毎日動くことで、Supabaseの無料プランの自動一時停止も防げる見込みです
