# 毎朝の通知（LINE）の設定手順

毎朝8時に、担当者ごとに「対応が必要な案件」をLINEで送る仕組みです。
誰も画面を開いていなくても届きます。サーバーを新しく立てる必要はありません。

判定の中身は画面の「対応が必要」とまったく同じです。新しい条件は作っていません。

**作業は1時間ほどです。** LINEとSupabaseの画面での操作はご本人にお願いします。
パスワードやAPIキーは誰にも渡さず、直接それぞれの画面に入力してください。

---

## 先に：何人まで無料で使えるか

LINEの無料プラン（コミュニケーションプラン）は **月200通** までです。
**1通＝1人宛て** で数えます。送る回数ではなく、受け取る人数の分だけ減ります。
使い切ると、その月はもう送れません（自動で課金されることはありません）。

| 受け取る人 | 月の通数（平日22日） | 判定 |
| --- | --- | --- |
| 6人 | 132通 | 余裕あり |
| 8人 | 176通 | 収まる |
| 9人 | 198通 | ぎりぎり。23営業日の月は超えます |
| 10人 | 220通 | **超えます**（ライトプラン 月5,000円が必要） |

**平日だけ送る設定にして、受け取る人を8人までにすれば無料で収まります。**
毎日（土日も）送る設定だと31日で割ることになるので、6人までです。

該当する案件がない日は送らないので、実際にはこれより少なくなります。
いまの残り通数は、設定画面の「LINE通知」に出る目安と、手順9の手動実行の結果で確認できます。

通数を減らしたいときは、受け取る人を減らすか、頻度を下げる（週2回にするなど）方法があります。

---

## 1. LINE公式アカウントを作る

[LINE Official Account Manager](https://manager.line.biz/) で、会社のアカウントを1つ作ります。
無料で、審査もありません。名前は「bring 案件管理」など分かりやすいものにしてください。

作ったら **設定 → 応答設定** で次のようにします。

- **応答メッセージ … オフ**（オンのままだと、自動返信が割り込みます）
- **あいさつメッセージ … オフ**（このシステムが自分で案内を返すため）
- **Webhook … オン**

## 2. Messaging API を使えるようにする

同じ画面の **設定 → Messaging API** で「Messaging APIを利用する」を押します。
このあと [LINE Developers](https://developers.line.biz/console/) の画面に進めるようになります。

LINE Developers で、作ったチャネルを開いて次の2つを控えます。
**どちらも他人に渡さないでください。**

| 名前 | ある場所 |
| --- | --- |
| チャネルシークレット | 「チャネル基本設定」タブ |
| チャネルアクセストークン（長期） | 「Messaging API設定」タブの一番下。「発行」を押すと出ます |

## 3. 友だち追加を受け取る関数を置く

Supabaseのダッシュボード → **Edge Functions** → **Deploy a new function**。

- 名前：`line-webhook`
- 中身：このフォルダの `functions/line-webhook/index.ts` を全部貼り付け
- **「Verify JWT」（JWTの検証）は必ずオフ** にしてください

LINEは鍵を付けずに呼んでくるので、検証をオンにすると弾かれてしまいます。
代わりにLINEが付ける署名を毎回確かめているので、第三者が偽の登録を送り込むことはできません。

配置できたら、関数のURLを控えます（`https://〇〇.supabase.co/functions/v1/line-webhook`）。

## 4. 通知を送る関数を置き直す

同じく **Edge Functions** で `daily-alert`（いまの名前は `bright-processor`）を開き、
`functions/daily-alert/index.ts` の中身を全部貼り直して Deploy します。

## 5. 鍵を登録する

Edge Functions → **Secrets** に追加します。

| 名前 | 値 |
| --- | --- |
| `LINE_CHANNEL_SECRET` | 手順2のチャネルシークレット |
| `LINE_TOKEN` | 手順2のチャネルアクセストークン（長期） |
| `APP_URL` | `https://rdbusinessunit.github.io/anken-kanri/` |

メールも併用するなら、前からある `RESEND_API_KEY` と `MAIL_FROM` はそのまま残しておきます。
使わないなら消してかまいません。

## 6. LINEに窓口のURLを教える

LINE Developers → 作ったチャネル → **Messaging API設定** → **Webhook URL**。
手順3で控えたURLを貼って、**「Webhookの利用」をオン**にします。

「検証」ボタンを押して **成功** と出れば、つながっています。

## 7. 全員が友だち追加する

LINE Developers の Messaging API設定にQRコードがあります。これを受け取る人に配って、
**全員に友だち追加してもらいます。**

追加すると「友だち追加ありがとうございます」と返ってきます。これが来れば登録できています。

## 8. 誰が何を受け取るか決める

ここからはシステムの画面です。**設定 → LINE通知** を開くと、
友だち追加した人の名前（LINEの表示名）が自動で並んでいます。

1人ずつ、次の2つを選びます。

- **受け取り方** … 「自分の担当分だけ」／「全担当のまとめ」／「受け取らない」
- **この人は誰？** … 案件の「営業担当」と同じ名前を選びます

所長やRDなど全体を見る人は「全担当のまとめ」にします。

いちばん上の **送信** を「送る」にして、**設定を保存** を押します。
止めたいときは「送らない」に戻せば、宛先を消さずに停止できます。

パネルの下に「受け取る人 ○人 → 月あたり最大 ○通」と出るので、
無料枠に収まっているかはここで確認できます。

## 9. 先に1回だけ試す

Supabase の Edge Functions の画面から `daily-alert` を手動で実行できます。

```json
{"ok":true,"送った":2,"送れなかった":0,"対象の案件":5,"LINEの残り通数":198,"失敗の内訳":[]}
```

このように返れば成功です。

- `送った:0` … 設定が「送らない」になっているか、受け取り方が全員「受け取らない」です
- `対象の案件:0` … 今日は対応が必要な案件がありません（正常です）
- `失敗の内訳` に理由が出ます

## 10. 毎朝動かす

SQL Editor で次を実行します。`<プロジェクトURL>` と `<service_role キー>` は
Settings → API の値に置き換えてください。**平日の毎朝8時（日本時間）**に動きます。

```sql
select cron.schedule(
  'anken-daily-alert',
  '0 23 * * 0-4',  -- UTC 日〜木の23:00 = 日本時間 月〜金の朝8:00
  $$
  select net.http_post(
    url     := '<プロジェクトURL>/functions/v1/daily-alert',
    headers := '{"Content-Type":"application/json","Authorization":"Bearer <service_role キー>"}'::jsonb
  );
  $$
);
```

土日も送るなら `'0 23 * * *'` にします（ただし無料枠は6人分までになります）。
時刻を変えるときは `23` の部分を直します（UTCなので日本時間マイナス9時間）。
止めるときは `select cron.unschedule('anken-daily-alert');` です。

動いたかどうかは `select * from cron.job_run_details order by start_time desc limit 10;` で見られます。

## 何を・誰に・いつ送るか（決定済み）

**送る条件（4つ）**

- 稟議が止まっている（簡易求人を発注したのに未上申／差戻しのまま／決裁が止まっている）
- 承認済みなのに③詳細が未入力で、面接・進捗報告ができない
- 求人の修正日を過ぎた
- 未着手の課題がある

承認後の条件変更とRD未確認は、画面には出しますが通知では送りません。

**宛先**

- 営業担当本人 … 自分が担当する案件だけ
- 所長・RD … 全担当分をまとめた一覧

**頻度**

平日の毎朝8時（日本時間）。該当する案件が1件もない日は送りません。

---

## メールも使いたいとき

メール（Resend）の仕組みも残してあります。LINEと同時に使えますし、LINEをやめて
メールだけに戻すこともできます。設定 → **メール通知（予備）** で切り替えます。

メールで自分以外の人に届けるには、Resend に自社ドメインを登録する必要があります
（DNSに3件追加：MXの `send`、TXTの `send`、TXTの `resend._domainkey`）。
`onboarding@resend.dev` のままだと、Resendに登録した本人にしか届きません。

## 注意

- 判定は `core.js` の `alertsFor()` と同じ内容を写したものです。**条件を変えるときは両方直してください。**
  片方だけ直すと、画面と通知で言うことが変わります
- LINEの1通は5000文字までです。案件が多くて入りきらないときは、件数だけを伝えます。
  分けて送ると通数が倍に増えてしまうためです
- 友だち解除した人は設定画面でグレーになり、送信の対象から外れます。
  また友だち追加すれば、前の割り当てのまま戻ります
- 対応が必要な案件が1件もない日は、通知を送りません
- この仕組みが毎日動くことで、Supabaseの無料プランの自動一時停止も防げる見込みです
